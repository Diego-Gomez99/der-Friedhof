# Project overview

## Game flow

1. `Main Menu` scene: Play calls `MainMenuManager.LoadGame`, Quit Game calls `MainMenuManager.QuitGame`.
2. `Final Scene`: the player walks with WASD / arrow keys. The active camera switches as the player crosses trigger colliders.
3. Touching an enemy sets game over. The Game Over panel shows two buttons wired to `GameManager.LoadScene(int)`: Play Again loads build index 1, Main Menu loads build index 0. Both fade to black and back in.
4. Reaching the `Endgame` trigger fades back to build index 0.

## Scripts

| Script | Role |
| --- | --- |
| `PlayerController` | Movement from `Horizontal`/`Vertical` axes in `FixedUpdate`, sets Rigidbody velocity and the animator floats `speed` and `turnSpeed`. Handles trigger contacts: tag `Enemy` ends the game, while the player stands in a trigger tagged `SS`, every `FixedUpdate` kills the enemies within 10 units (tracked with enter/exit counts, because `OnTriggerStay` stops while the Rigidbody sleeps). Stops moving while `GameManager.instance.isGameOver` is true. |
| `GameManager` | Singleton (`GameManager.instance`) present in every gameplay scene. Finds the object named `Game Over Panel` in `Awake`, hides it, and shows it when `GameOver()` is called. `LoadScene` darkens the used button and fades to the scene through `SceneFader`. It ignores every call after the first, because the Game Over buttons click on press and on release. Also starts the soundtrack. |
| `Enemy` (file `EnemyAI.cs`) | Chases the player once within `DetectionDistance`. Hidden until then, only the closest eligible enemy is shown, and it vanishes and reappears in smoke by distance, time or a closer enemy taking over. `Attack()` plays its scythe swing when it kills the player; `Die()` disables its colliders and destroys it after a delay. See `enemy-behaviour.md`. |
| `MainMenuManager` | Menu music and the Play and Quit handlers. Play fades into the game scene and Quit fades to black before quitting, both through `SceneFader`. |
| `SceneFader` | Static helper that loads a scene behind a fade to black and back, or fades to black and quits, see `known-issues.md` (Scene transitions). |
| `MenuButtonEffect` | On the `Play` and `Quit Game` buttons of `Main Menu` and the `Play Again` and `Main Menu` buttons of the Game Over panel in `Final Scene`. Grows and brightens the label while hovered or selected. Hovering selects the button in the EventSystem. Invokes the button's `onClick` on mouse press, so the handlers run again on release and must ignore the second call. |
| `CamerasController`, `FollowCamera`, `StaticCamera` (in `CamerasScripts/`), `SwitchCameraCollider`, `CameraController` | Per-area cameras and switching between them. |
| `Checkpoint` | Saves the player position to `PlayerPrefs`. The loading side in `PlayerController` is commented out, so checkpoints currently have no effect. |
| `SlashEffect` | Full-screen slash, hit-stop, shake and slice sound played when an enemy touches the player. Created at runtime by `SlashEffect.Play`. |
| `DeathMarkers` | Static class, not a component. When the killer's scythe is fully planted, `Enemy.LateUpdate` calls `DeathMarkers.Record`, which keeps the scythe's world pose and scene name in a static list. On every `sceneLoaded` of that scene it builds a `Death Marker` object per entry, with only a `MeshFilter` and `MeshRenderer` copied from an enemy's `weapon` (no collider, untagged), so the scythes mark where the player died, each with a `ScytheGroundMark` rebuilt from the seed of the one left when it was planted. The list lasts until the game is closed, so the markers survive Play Again and trips through the main menu; in the editor it is cleared on entering Play mode. |
| `GroundImpactEffect` | Burst of dust and dirt clods where an enemy's scythe butt first touches the ground during the attack (or where it is planted, if it never reaches the ground). Built at runtime by `GroundImpactEffect.Play`, uses the always included `Sprites/Default` shader and destroys itself after 2.5 s. |
| `ScytheGroundMark` | Mound of turned earth around the handle of a planted scythe: a lumpy ridge with a funnel where the handle goes in and a few clods, about 0.9 m across, built as one mesh at runtime from a seed. `Enemy.LateUpdate` creates it, heaving up over 0.2 s, where the handle crosses the ground (the enemy's feet height) when the plunge bottoms out. It follows the terrain's slope and uses the dominant terrain layer's texture, darkened, with the same tiling (plain dark earth if there is no terrain at that height), on a URP/Lit material so it is lit and fogged like the ground. It stays until the scene unloads. |
| `SmokeEffect` | Puff of black smoke around an enemy as it appears or disappears. Built at runtime by `SmokeEffect.Play` like `GroundImpactEffect`, with a noisy soft puff texture generated in code, and destroys itself after 3 s. `PlayTrail` is the thin trail between where an enemy vanished and where the next appears: its head crosses in 0.3 s at about a third of the body's height, emitting a puff every 0.25 m by hand (at most 160, spaced out further on long trails). It can also follow a path with corners (`PlayTrail` with an array of points). Once there it lingers for the `holdTime` it is given (the enemy passes `AppearAfterTrailPause`), puffing 30 times a second around its end until the enemy appears. |
| `VirtualJoystick` | On-screen joystick for touch screens, built at runtime by `VirtualJoystick.Create` (called from `PlayerController.Start`) on every platform. On phones and tablets (`Application.isMobilePlatform`) it rests faintly in the bottom-left corner from the start; elsewhere it stays invisible until the screen is first touched (remembered in a static flag across scene loads). It jumps under the first finger that touches the screen. Gating it on `Input.touchSupported` did not work: in the WebGL build that is true on desktop browsers without a touch screen, so the joystick showed while playing with the keyboard. `PlayerController` adds the static `Value` to the `Horizontal`/`Vertical` axes. Hidden during Game Over; its canvas does not block raycasts, so the Game Over buttons still take taps. |
| `WalkSteps`, `LampEffect`, `HeadFalling`, `AreaNameShow` | Footstep audio and ambience effects. |
| `LimitFPS` | Caps the frame rate at 60. |

## How the player dies

The enemy has a child named `weapon` with a `BoxCollider`, plus a `CapsuleCollider` on the root. `PlayerController.OnTriggerEnter` checks the `Enemy` tag, sets `GameManager.instance.isGameOver = true`, plays the death animation and sound, and shows the Game Over panel once the animation ends (see `player-death-feature.md`). The enemy keeps its chase behaviour.

## Assets worth knowing

- Player animator: `Assets/Animations/PlayerAnimations.controller`. A blend tree state named `Movement`, driven by `speed` and `turnSpeed`, and a `Death` state entered from Any State by the `die` trigger.
- Enemy model and animator: the 32 enemies in `Final Scene` are instances of `Assets/Prefabs/SkeletonEnemy.prefab`, still named `CB_squeleton_lowpolywithoutacc (n)`, which override only their name and Transform. The prefab is a variant of `Assets/Animations/Enemy Animations/T-Pose.fbx` (the Dead Cowboy skeleton rigged with Mixamo, humanoid) that adds the `Enemy`, `Rigidbody`, `CapsuleCollider`, `AudioSource` and configured `Animator` components and the `weapon` child, so enemy changes are made once in the prefab. `Assets/Prefabs/Enemy.prefab` is an older, unrelated enemy built from planes; its only use in `Final Scene` is the inactive `Enemy (1)`. The rigged model's origin is at the feet (the unrigged one had it at the body centre), so the enemy `CapsuleCollider` centre is at y = 0.909, half its height. Their controller is `Assets/Animations/CB_squeleton_lowpolywithoutacc.controller`: `idle` plays `Enemy Animations/Idle.fbx` and `EnemyWalking 0` plays `Enemy Animations/Wheelbarrow Walk (1).fbx` while `Persiguiendo` is true, at a rate set by the float `walkSpeed` (the enemy's actual horizontal Rigidbody speed divided by `WalkClipSpeed`, 1.8 m/s, so a blocked enemy freezes mid-step), and `Attack` plays `Enemy Animations/Enemy Attack.fbx` on the `attack` trigger. `Enemy.LateUpdate` overrides the right arm after the Animator so it points back and `ArmDropAngle` degrees down, opened `ArmOpenAngle` degrees to the enemy's right, and moves the scythe (`weapon`, a child of the enemy root), with the local rotation it has in the scene, so that `WeaponGripPoint` sits in the right hand. The scythe's `BoxCollider` is the trigger that kills the player; its centre is shifted back every frame so the kill zone stays at the authored height (at shoulder height it passes over the player). All 32 enemies take the `weapon` Transform and `BoxCollider` values from the prefab. The unrigged `Quixel/.../DeadCowboy/CB_squeleton_lowpolywithoutacc.fbx` has no bones and cannot be animated; `EnemyWalking.anim` is an empty clip.
- Safe spots: the six `SS` objects in `Final Scene` are instances of `Assets/Prefabs/SS.prefab`, a ProBuilder hexagon whose `MeshRenderer` is disabled, so only its trigger `MeshCollider` is left. Each one sits under a `StreetLampRound2A` (unnamed, `(5)`, `(6)`, `(8)`, `(9)`, `(10)`) whose `Spot Light` and `Point Light` are overridden in the scene to green, with the 92° spot angle that all lamps already override, so the lamp marks the spot by casting a green pool on the ground. The other lamps keep the prefab's warm light.
- Animation clips: `Assets/Animations/` (Mixamo-style FBX: idle, walking, running, strafes, turns, jump, dying).
- Audio: `Assets/Audios/` has the footsteps and the player death scream. `Assets/Horror Elements/` has ambience and hit sounds (for example `Hits/Hit_Drama.wav`).
- Fonts: the horror fonts in `Assets/Fonts/` are TextMeshPro SDF assets in dynamic mode, so TMP adds glyphs from the `.ttf` on demand. The character sets are small: `horrh___` (Game Over title) has letters, digits, space and `! $ . ?`; `HorrorFont-Regular` (buttons) has only letters and space. Other characters, such as `-`, are drawn with TMP's default font, LiberationSans.
- Both `.ttf` files were edited to add an underscore, because TMP warns about a missing Underline character on every text that uses a font without one. The `_` is the last glyph in each font, so existing glyph indices, which the font assets store, did not change. The optional `hdmx` (`horrh___`) and `DSIG` (`HorrorFont-Regular`) tables were dropped because they were no longer valid. Any further edit to these fonts should also append glyphs at the end.
- TMP remembers characters it failed to find in a font until the next domain reload. After changing a `.ttf`, enter Play mode (or recompile) before judging whether a font warning is gone.
- Unity's native font engine keeps the previously loaded `.ttf` in memory even after the file is reimported, and reimporting the `SDF.asset` does not clear it. If an existing glyph's outline changes, discard the glyph TMP already added to the `SDF.asset` (`git checkout` it) and restart the editor before checking the result; otherwise the old outline is drawn into the atlas again. Check the glyph's `m_Metrics` in the `.asset` diff to confirm which version was used.
